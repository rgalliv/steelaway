# Verification

What has to be checked against a source before it is acted on. This is the
shortest file here and the most important.

## Always verify

| Output | Against |
|---|---|
| Any member weight, section property, capacity | Current AISC Manual, or mill certified data |
| Any tolerance — fabrication, erection, weld, bolt | Governing specification and AISC standards |
| Any code or regulatory statement | The current published text |
| Any quoted contract language | The executed contract |
| Any drawing reference | The actual sheet at the actual revision |
| Any date or duration in a claim | Your own correspondence records |
| Any quantity | Your takeoff and the drawings |

## Never delegate

These are determinations held by qualified, licensed, or legally responsible
people. A prompt can organize the inputs and ask the questions. It cannot decide.

- **Structural adequacy** — engineer of record
- **Connection design** — the engineer with design responsibility
- **Erection stability and temporary bracing** — qualified erection engineer
- **Crane picks and rigging** — qualified rigger and lift planner
- **Hazard determination and JHA approval** — competent person on site
- **Contract enforceability** — counsel
- **The number on the bid** — you

## The failure mode to watch for

A language model produces fluent, confident, specific text whether or not the
underlying fact is right. A wrong tolerance reads exactly like a right one. This
is not a reason to avoid the tool; it is the reason every template in this
library ends with a verification step and forbids invented values.

Treat output as **a well-organized draft by a capable assistant who has not seen
the drawings.** That framing gets the value out of it without the exposure.

## A practical habit

When Claude gives you a number you did not supply, ask: *"Where does this come
from? Did I give it to you, or did you produce it?"* The answer is usually
immediate and honest, and it tells you which numbers need the book.
